ORBIT dual-agent stage execution architecture

To enforce speed and strict governance simultaneously, every agent stage in the pipeline runs on a two-agent model.

1
The Builder Agent Execution & speed
Generates stage-specific artifacts — requirements, BDD stories, code, test scripts, or canary configs — using specialized LLM prompts, context memory, and tool integration.
Builds on existing tools: Citi’s existing AI coding assistants and Devin agents fill the builder role — all running on Arc, all judged the same way.
→
2
The Judge Agent Governance & quality gate
Evaluates the Builder Agent’s output against stage-specific, artifact-aware rubrics — requirement stability, BDD verifiability, or NFR coverage.
Deterministic first: SAST/DAST, tests, and schema checks run as tools; the LLM judge covers only what tools can’t assess.
An artifact promotes to the next stage, or triggers the CI/CD gate, only when the Judge Agent issues an explicit pass certification — and, on high-risk stages, a named human reviewer signs off.

Keeping the judges honest

  • Different model family from the builder, to avoid self-preference bias.
  • Golden-set calibration: judge–human agreement measured with Cohen’s kappa, not a point delta.
  • Judges are versioned and evaluated like any model, with independent validation by the second line.
  • Phase containment feedback: an escaped defect tightens the rubric of the stage that missed it.

Autonomy levels, set by risk tier

L1 · SuggestHumans decide and author
L2 · Drafts, human approvesNamed approver before it moves on
L3 · Acts, human reviewsReviewed asynchronously, reversible
L4 · Autonomous checkDeterministic gates only, overrides logged
No stage auto-deploys to production: the release agent is L2 on high-risk tiers.
The two CI/CD promotion gates are hard, automated checks rather than a builder–judge pair. Every agent runs on Arc, which governs the agents themselves; ORBIT governs what they produce.
Why artifact-aware quality gates matter at enterprise scale: a single generic quality rubric produces weak signal and papered-over risk. “Quality” means something very different for a BDD scenario (is the Then clause deterministic and automated?) than for an NFR architecture spec (can Dev, QE, and Performance teams execute against it without manual translation meetings?). By embedding artifact-aware judge agents and hard CI/CD promotion gates at every stage, this framework gives Risk, Controls, and Engineering executives an Artifact Quality Score and a DORA-aligned Velocity Scorecard they can trust — delivering software faster.
